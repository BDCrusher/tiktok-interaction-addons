# Sound button actions — development beta

This is a separate selectable patch in TikTok Interaction Add-ons **0.5.1-beta.1**, not a HushFeed fork or part of Enhanced collection popup. Selection defaults off; runtime enable defaults on once selected. Target: original global TikTok 47.1.4 / 2024701040 with external **HushFeed 0.74.0 Settings**. This repair updates the shared settings constructor/layout after upstream removed its badge API. Sound behavior from 0.5.0 is retained; compiled/simulated checks are not phone acceptance. See [COMPATIBILITY.md](COMPATIBILITY.md). No APK is distributed or installed automatically.

## Behavior and settings

Settings: **HushFeed → Your feed → BDCrusher's Settings → Sound button actions**, after Feed screen when available. With no feed routes selected, find the root under Personal add-ons before Hushfeed's own group. Public native header/palette/card/switch helpers are used. Sound appears only when selected, including with its runtime toggle off; hidden controls stay hidden. Preferences remain `sound_actions_addon_v1` through the app context, not a fixed package name. Reset affects only that file; HushFeed backup/search do not include these preferences. Counts refresh as summary text, never through the removed upstream badge setter.

A normal music-disc tap remains native. A hold opens a bounded menu, capped at 60% of available screen height. Drag onto a visible row and release, or release over the disc and tap a row. Holding/releasing on the disc alone never triggers a save. Moving beyond touch slop before the hold cancels enhancement. Multitouch, cancellation, detach, rebind or changed track cancel selection. Popup rows scroll through Android's ScrollView, with ordinary row touch cancellation during scrolling.

Touches are captured only inside a bound visible eligible disc before parent speed timers. While deciding hold versus tap, the native disc receives feedback events directly. A valid short tap cancels that target, then replays original DOWN/UP through the full original Activity dispatch (including native custom delegates). This restores the native sound-page click path instead of assuming the placeholder disc is clickable. A depth guard avoids duplicate enhancement; the native UP cancels timers. Successful holds and cancelled/moved/multitouch sequences never replay. Outside/hidden/disabled/invalid/paused cases stay stock.

**Gesture status** on this page shows session-only window events, bound/eligible discs, captured presses and menus opened. It refreshes when returning or toggling the feature. If a hold still fails, return here and share that readout, the version and the feed/search/sound route. Counters reset on process restart; no song IDs, provider objects, user data or credentials are recorded.

The first action requests native Save sound to TikTok. Additional rows use TikTok's filtered per-song eligible destination data, preserving order and removing duplicates. When feed data is empty, a non-action Checking music apps footer appears while TikTok's existing authenticated detail client loads richer data. Up to two native IDs are checked within four seconds: the current sound and its explicitly declared matched recording. Unrelated/recommended songs are rejected. No installed-app enumeration, text search, guessed links or cross-service matching. On no result/failure the footer disappears and TikTok saving remains. A matching title component in the same window is required for native add-song context; each provider is revalidated at selection. Dismissal, rebind, detach and track change cancel obsolete work. New rows never silently become selected under a stationary finger.

The popup follows the same host sheet background and HushFeed applied dark/AMOLED color as Favorites. It uses Favorites' observed width when available, otherwise the inspected native 212 dp maximum-width fallback, clamped to the screen. Selection uses the same 15% contrasting highlight and native Favorites haptic routine on open/row change/activation. Hover compares screen coordinates including the popup window's origin and clipped visible rows. HushFeed Turn off haptics/device restrictions may suppress vibration; no forced bypass. No global color rewriting or Favorites remap override.

## Native hook evidence and code

The supplied APK contains the music-service implementation inside a ZIP-shaped `lib/arm64-v8a/libdex_df_music_dsp.so`, described by `assets/dynamic_feature_install/df_music_dsp.json`. It is not absent merely because its implementation is missing from top-level DEX files. Research copies/decompiled files remain outside this distributable source.

- `VideoMusicCoverAssem.z4(Object)` supplies current VideoItemParams and its disc. `VideoMusicTitleAssem.z4(Object)` supplies the native title/context owner. Matching uses the same current track and Activity window, not strict Java object identity between independently bound parameters or a global last song. Unbind removes associations.
- The alternate `LLLLLLLLL` cover container is also registered. A safe `onViewCreated(View)` wrapper reads the native current item via `ReusedAssem.rq()` after view inflation, covering early binding and view recreation. It is installed after all execute-time upstream fingerprints have inspected the original method.
- `X.03uJ.dispatchTouchEvent(MotionEvent)` is the common native window dispatcher reached by MainActivity and DetailActivity. Its original Activity/custom-delegate calls and ancestry are validated. The disc-only early guard precedes both paths and passes all other input to them unchanged. Direct disc dispatch uses a depth guard to avoid updating the hold twice through `X.07pb`.
- Existing `X.07pb.onTouch(View, MotionEvent)` is wrapped to preserve its original arguments and press feedback, then calls the scoped add-on handler; native and add-on consumption results are combined. No replacement OnClickListener or generic video long-press handler is installed. The native edge timer listener is guarded at entry: a press starting inside an enabled visible disc's clipped hit area skips that listener for the whole sequence, including its UP/CANCEL tail. Presses elsewhere remain stock. Unsupported fingerprints fail patching.
- `X.0Af8.LJJJJI(Music)` delegates to `MusicAddToDspCoreServiceImpl`: native filtering requires a nonempty provider song ID, native provider/access checks and native availability checks. The add-on passes these objects opaquely; it does not read their token fields.
- Native `MusicDetailApi$DetailApi.queryMusic(String,int)` returns ListenableFuture, annotated with `/aweme/v1/music/detail/`, `music_id` and `click_reason`. The bridge uses reason zero through TikTok's existing client. `MusicDetail.music`/`matchedPgcMusicInfo` are accepted only for successful status and validated native IDs. `SongLookup` uses a bounded daemon executor (two workers/two queued jobs), timeout and cancellation; the UI callback rejects stale request generations/track state. No new network client or provider credential handling.
- A finalization-time `X.0yck.Qk(List)` wrapper observes Favorites width after its existing body, without replacing its UI. Shared `NativeUiBridge.haptic(Context)` calls `X.0d6x(Context).LIZ(0)`, the routine used by native Favorites. These helpers work with Sound selected alone too.
- `VideoMusicTitleAssem.Qr(...)` builds the native AddSongContextData; `X.09JO.LIZ(VideoItemParams)` supplies its native entrance context. `X.0Af8.LJJIIZ(...)` enters TikTok's native add-song dispatcher, which handles networking, auth/linking, errors and provider-specific behavior. The add-on never reads a token or writes to a music app itself.
- TikTok sound saving creates a native MusicCollectViewModel, supplies its current music ID and calls `xU2()`. Its default uncollected state requests **add**, not a destructive unfavorite toggle; the native coroutine/API, error and event flows remain TikTok's. This invocation still needs device confirmation outside the sound-page lifecycle.

Source: `patches/src/main/kotlin/app/soundaddon/patches/SoundPatch.kt` binds exact APK references; `extensions/sound/src/main/java/app/soundaddon/runtime/` contains NativeBridge, SoundRuntime, SoundPolicy, SoundPreferences and SoundSettings. Compile-only HushFeed declarations are excluded from the payload. The collection engine remains unchanged; both modules use the repaired shared settings wrapper.

## Known limits — not release acceptance

This is **not phone-verified**. Successful DEX compilation cannot prove native ViewModel initialization, correct account linking, playlist destination, on-screen positioning or gesture delivery after opening a popup window.

Native detail fetching is now implemented, but exact server/account responses, regional/provider eligibility, dynamic-feature initialization and native save/auth flows still require device confirmation. A corresponding current native title component is needed; if unavailable, external rows are omitted. The patch does not claim exhaustive detection for every original sound/remix/song or parity with every sound-page experiment. Native auth may require confirmation; returning from dispatch is not proof of a successful playlist save.

No TalkBack long-click action has been added; touch gestures, TalkBack interaction with the open popup, system Back, rotation and large-font scrolling all need real-device testing. These are beta limitations, not verified accessibility claims. Other TikTok versions or HushFeed releases are unsupported until separately checked.

## Device checklist

Test original taps; hold without moving; drag/release on each row; release outside; pre-hold scrolling; popup scrolling; cancel/multitouch; detach, rapid track changes and dismissal. Confirm no accidental or duplicate saves and no unfavorite of an already saved sound. Confirm native failure feedback and account linking for linked/unlinked YouTube Music and each available provider. Compare the hold menu to the same track's stock sound-page button.

Check light/dark/AMOLED/custom color, large fonts, RTL, rotation, Back and TalkBack; native width before/after opening Favorites; actual vibration with haptics allowed/suppressed. Check pause/safe mode, hidden disc, clear display, Favorites remapping, changed app identity and both selection orders. Test Sound alone and both features. Compare known sound-page YT Music destinations, matched originals/remixes, offline/timeouts and changing songs while loading. A dedicated accessible disc long-click path remains future work.

## Build and install

Use the pinned toolchain in BUILDING.md. Build with `gradlew.bat :patches:generateMetadata :patches:packageSource :extensions:sound:testDebugUnitTest :extensions:sound:lintDebug :extensions:collections:testDebugUnitTest`. Set ANDROID_HOME to the local SDK first. The renamed bundle/source ZIP are in dist; checksum/payload audits are generated.

In Morphe Expert mode select usual **HushFeed 0.74.0** patches, including Settings, and **Sound button actions** against the original TikTok APK in one run. Select Collections only if wanted. Replace the old add-on source, never select two copies. Keep your signing key; no automatic uninstall/install. Manager 1.34.0+ is HushFeed's stated floor; the user's newer development stack remains device-unverified. No other HushFeed/PineDrama compatibility is claimed. A [GitHub source/update feed](PUBLISHING.md) is available; fetching an updated bundle still requires repatching TikTok to apply it.
